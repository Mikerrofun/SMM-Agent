# Architecture — SMM Agent

Документ описывает структуру проекта, используемые технологии и принципы
организации кода. На данном этапе это скелет проекта — бизнес-логика будет
добавляться поверх этой структуры.

## Технологический стек

| Технология              | Назначение                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| Next.js (App Router)    | Каркас приложения и HTTP-слой (Route Handlers, без фронтенда)      |
| Node.js + TypeScript    | Среда исполнения и статическая типизация                          |
| Prisma + @prisma/client | ORM и типобезопасный доступ к базе данных                         |
| Supabase (PostgreSQL)   | Хостинг базы данных                                               |
| OpenAI                  | Генерация идей и постов                                           |
| grammy                  | Telegram-бот (доставка идей, подтверждение выбора)               |
| node-cron               | Планировщик задач (анализ конкурентов по расписанию)             |
| zod                     | Валидация входных данных и env-переменных                        |

## Структура папок

```
src/
├── app/
│   └── api/
│       └── health/       # health-check эндпоинт (проверка работоспособности)
├── ai/                   # взаимодействие с OpenAI (запросы, парсинг ответов)
├── bot/                  # Telegram-бот на grammy (хендлеры, клавиатуры)
├── parser/               # парсинг публикаций каналов конкурентов
├── cron/                 # scheduled tasks (запуск анализа по расписанию)
├── services/             # бизнес-логика (оркестрация парсинга, идей, генерации)
├── repositories/         # работа с БД через Prisma (CRUD, запросы)
├── db/                   # инициализация Prisma client
├── prompts/              # AI-промпты в .md файлах (стиль, методология, шаблоны)
├── core/
│   ├── config/           # конфигурация приложения, чтение env
│   └── lib/              # инициализация внешних клиентов (OpenAI, bot, cron)
└── shared/
    ├── utils/            # вспомогательные функции
    ├── types/            # общие типы и интерфейсы
    └── constants/        # константы приложения

prisma/                   # схема Prisma и миграции (добавляются позже)
docs/                     # проектная документация
```

## Принципы организации кода

- **Разделение слоёв.** HTTP/точки входа (`app/api`, `cron`, `bot`) не содержат
  бизнес-логику — они вызывают `services`.
- **services** — оркестрация бизнес-процессов: парсинг → анализ → идеи →
  генерация. Не знают деталей доступа к БД.
- **repositories** — единственное место, где выполняются запросы к базе через
  Prisma. Остальной код не обращается к БД напрямую.
- **db** — создаёт и экспортирует единственный экземпляр Prisma client.
- **prompts** — промпты хранятся как `.md` файлы отдельно от кода, чтобы их можно
  было редактировать без изменения логики.
- **core/config** — централизованное чтение и валидация env-переменных (через
  zod), чтобы остальной код получал уже проверенную конфигурацию.
- **core/lib** — фабрики/синглтоны внешних клиентов (OpenAI, Telegram-бот).
- **shared** — переиспользуемые утилиты, типы и константы без привязки к домену.

## Точки входа

- `src/app/api/health/route.ts` — health-check (`GET /api/health`).
- В дальнейшем: cron-задачи (`src/cron`), запуск Telegram-бота (`src/bot`).
