## Как это работает

### 1. Команда `/ideas`

Когда кто-то вызывает `/ideas`, идеи отправляются **ВСЕМ подписчикам** из `SUBSCRIBER_CHAT_IDS`:

```
Любой юзер → /ideas
  ↓
getNewIdeasForSending(10) ← получаем NEW идеи из БД
  ↓
Для каждого ID в SUBSCRIBER_CHAT_IDS:
  • bot.api.sendMessage(chatId, idea) с кнопкой "Сгенерировать пост"
  ↓
markIdeasAsSent() ← помечаем как SENT (один раз для всех)
```

**Важно:** Идеи помечаются как `SENT` только один раз, чтобы не отправлять их повторно.

### 2. Автоматический cron

Когда срабатывает cron (вт/чт в 9:50 MSK):

```
CRON запуск
  ↓
Отправка уведомления о начале → ВСЕМ подписчикам
  "🤖 Автоматический запуск pipeline..."
  ↓
runFullPipeline() → парсинг + AI + дедупликация
  ↓
Формирование детального отчёта через formatPipelineReport()
  ↓
Отправка детального отчёта → ВСЕМ подписчикам
  ✅ Статистика: каналы, идеи, дедупликация, время
```

**Важно:** 
- **ВСЕ подписчики** получают одинаковый **детальный отчёт**
- Отчёт форматируется один раз через утилиту `pipelineReportFormatter.ts`
- Никакого разделения на "админ/юзер" — все равны
- Первый ID в списке технически используется для ctx, но получает тот же отчёт

## Архитектура

### Утилита форматирования отчётов

```typescript
// src/shared/utils/pipelineReportFormatter.ts

formatPipelineReport(result: PipelineResult, duration: number): string
  ↓
  Возвращает HTML-форматированный отчёт для Telegram
  
formatDuration(seconds: number): string
  ↓
  "2 мин 30 сек" или "45 сек"
  
pluralizeNewIdea(count: number): string
  ↓
  "новая идея" / "новые идеи" / "новых идей"
```

**Преимущества:**
- ✅ Один источник правды — логика форматирования в одном месте
- ✅ Переиспользуется в `runPipeline.ts` и `scheduler.ts`
- ✅ Легко тестировать и изменять
- ✅ Нет дублирования кода

### Логирование

```typescript
// Для сервера (консоль)
logPipelineStats(result, duration) → console.log()

// Для Telegram (HTML)
formatPipelineReport(result, duration) → string (HTML)
```

Обе функции нужны, но выполняют разные задачи:
- **`logPipelineStats`** — для мониторинга на сервере (разработчику)
- **`formatPipelineReport`** — для пользователей в Telegram

## Настройка подписчиков

### Шаг 1: Узнать Telegram ID

Каждый пользователь должен узнать свой ID через [@userinfobot](https://t.me/userinfobot):
1. Написать боту
2. Получить числовой ID (например: `6788213640`)

### Шаг 2: Добавить в .env

```bash
# Первый ID = главный админ (получает детальные отчёты)
SUBSCRIBER_CHAT_IDS="6788213640,1234567890,9876543210"
```

### Шаг 3: Перезапустить бота

```bash
npm run bot
```

## Поведение команд

### `/ideas` - рассылка идей

- ✅ Отправляет NEW идеи **всем** подписчикам
- ✅ Помечает идеи как `SENT` (один раз)
- ✅ Каждый получает кнопку "✍️ Сгенерировать пост"

### `/run_pipeline` - ручной запуск

- ✅ Отправляет детальный отчёт **только инициатору** (тому кто вызвал)
- ❌ Не отправляет идеи автоматически (нужно вызвать `/ideas`)
- ℹ️ Это единственная команда, которая НЕ рассылает всем

### CRON - автоматический запуск

- ✅ **ВСЕ** подписчики получают уведомление о начале
- ✅ **ВСЕ** подписчики получают детальный отчёт
- ✅ Предлагает вызвать `/ideas` для получения идей
- ℹ️ Первый ID (ADMIN_CHAT_ID) технически используется для ctx, но все получают одинаковые сообщения

## Преимущества

1. **Один источник правды** - идеи получаются из БД один раз
2. **Нет дублирования кода** - форматирование отчётов в одной утилите
3. **Все равны** - все подписчики получают одинаковые сообщения
4. **Масштабируемо** - легко добавить/удалить подписчика через `.env`
5. **Обработка ошибок** - если кто-то заблокировал бота, остальные всё равно получат сообщения
6. **Простота** - нет сложной логики разделения на "админ/юзер"

## Как добавить нового подписчика

1. Попросите пользователя узнать свой ID через [@userinfobot](https://t.me/userinfobot)
2. Добавьте ID в `.env`: 
   ```bash
   SUBSCRIBER_CHAT_IDS="старые_айди,новый_айди"
   ```
3. Перезапустите бота: `npm run bot`

Готово! Новый пользователь будет получать идеи при следующем вызове `/ideas` или автоматическом запуске cron.
