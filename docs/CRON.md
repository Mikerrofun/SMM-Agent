# Автоматический запуск (Cron)

## Описание

SMM Agent автоматически запускает pipeline генерации идей по расписанию с помощью встроенного планировщика на базе `node-cron`.

По умолчанию: **каждый вторник и четверг в 10:00 МСК** (7:00 UTC).

---

## Как это работает

1. **При запуске бота** автоматически инициализируется планировщик
2. **По расписанию** запускается тот же pipeline, что и при команде `/run_pipeline`
3. **Результаты отправляются** администратору в Telegram
4. **Ошибки логируются** и отправляются уведомлением

---

## Конфигурация

### Переменные окружения

```bash
# Включить/выключить автоматические запуски
CRON_ENABLED=true

# Расписание в формате cron (UTC timezone)
CRON_SCHEDULE="0 7 * * 2,4"

# Chat ID администратора для уведомлений
ADMIN_CHAT_ID=123456789
```

### Формат CRON_SCHEDULE

Формат: `"минута час день месяц день_недели"`

**Примеры:**

```bash
# Вторник и четверг в 10:00 MSK (7:00 UTC)
CRON_SCHEDULE="0 7 * * 2,4"

# Каждый день в 10:00 MSK
CRON_SCHEDULE="0 7 * * *"

# Понедельник, среда, пятница в 12:00 MSK (9:00 UTC)
CRON_SCHEDULE="0 9 * * 1,3,5"

# Каждый час
CRON_SCHEDULE="0 * * * *"
```

**День недели (последняя цифра):**
- 0 = Воскресенье
- 1 = Понедельник
- 2 = Вторник
- 3 = Среда
- 4 = Четверг
- 5 = Пятница
- 6 = Суббота

## Получение ADMIN_CHAT_ID

1. Откройте Telegram
2. Найдите бота [@userinfobot](https://t.me/userinfobot)
3. Отправьте ему `/start`
4. Скопируйте ваш `Id` (число)
5. Добавьте его в переменную `ADMIN_CHAT_ID`

## Timezone (Часовые пояса)

### Railway и большинство хостингов работают в UTC

**Важно:** Все cron-выражения указываются в **UTC** времени.

### Конвертация времени

| Ваше время | UTC время | Cron выражение |
|------------|-----------|----------------|
| 08:00 MSK  | 05:00 UTC | `0 5 * * *`    |
| 10:00 MSK  | 07:00 UTC | `0 7 * * *`    |
| 12:00 MSK  | 09:00 UTC | `0 9 * * *`    |
| 14:00 MSK  | 11:00 UTC | `0 11 * * *`   |
| 18:00 MSK  | 15:00 UTC | `0 15 * * *`   |

**Формула:** UTC = MSK - 3 часа

## Troubleshooting

### Cron не запускается

**Проверьте:**
1. ✅ `CRON_ENABLED=true` (или переменная не установлена)
2. ✅ `ADMIN_CHAT_ID` указан правильно
3. ✅ Бот запущен и работает
4. ✅ Cron-выражение корректное

**Логи должны показать:**
```
[CRON] ✅ Планировщик успешно запущен
```

### Cron запускается, но ничего не происходит

**Проверьте:**
1. ✅ `ADMIN_CHAT_ID` — это именно ваш личный chat ID
2. ✅ Вы написали боту `/start` хотя бы раз
3. ✅ Бот не заблокирован вами

**Тест:** Отправьте боту `/run_pipeline` вручную. Если работает — cron тоже будет работать.

### Неправильное время запуска

**Проблема:** Cron запускается не в то время.

**Решение:** Помните, что `CRON_SCHEDULE` использует **UTC** время, а не локальное.

Конвертируйте ваше время в UTC:
- 10:00 MSK = 07:00 UTC → `"0 7 * * *"`
- 14:00 MSK = 11:00 UTC → `"0 11 * * *"`

## Рекомендации

1. **Тестируйте локально** перед деплоем:
   ```bash
   npm run bot:dev
   # Отправьте /run_pipeline в бота
   ```

2. **Мониторьте логи** первые несколько дней после деплоя

3. **Настройте ADMIN_CHAT_ID сразу** — без него cron будет пропускать запуски

4. **Используйте разумное расписание** — 2 раза в неделю достаточно для большинства случаев

5. **Проверяйте лимиты OpenAI** — автоматические запуски тратят API кредиты

```

    │
    ├─→ Каждый вторник и четверг в 7:00 UTC
    │
    ▼

    ├─→ Создает фейковый Context для Grammy

    ├─→ Дедупликация
    │
```

## Дополнительно

### Изменение расписания без редеплоя

На Railway измените переменную `CRON_SCHEDULE` и сервис автоматически перезапустится с новым расписанием.

### Несколько расписаний

Если нужно несколько разных расписаний, можно модифицировать `src/cron/scheduler.ts`:

```typescript
// Первое расписание: вт и чт в 10:00
cron.schedule("0 7 * * 2,4", () => void runScheduledPipeline());

// Второе расписание: пятница в 15:00
cron.schedule("0 12 * * 5", () => void runScheduledPipeline());
```
