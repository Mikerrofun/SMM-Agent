# Часть 1. Что такое embeddings (простыми словами)

## Проблема

Нам нужно понять: **«похожа ли новая идея на то, что Наталья уже писала (или на
идею, которую мы уже придумали в этом прогоне)?»**

Сравнивать текст «по буквам» бесполезно. Два поста могут быть про одно и то же
разными словами:

* «Как перестать откладывать дела на потом»
* «Борьба с прокрастинацией: первый шаг»

По буквам совпадений почти нет, а по смыслу это одна тема. Нам нужно сравнение
**по смыслу**, а не по словам.

## Идея embeddings

Embedding — это способ превратить текст в **список чисел** (вектор), который
описывает *смысл* этого текста.

```
"как перестать откладывать дела"  →  [0.12, -0.45, 0.88, ... ]   (1536 чисел)
"борьба с прокрастинацией"         →  [0.13, -0.42, 0.85, ... ]   (1536 чисел)
"рецепт борща"                     →  [-0.77, 0.30, 0.02, ... ]   (1536 чисел)
```

Магия в том, что **близкие по смыслу тексты дают близкие векторы**. Первые два
вектора будут почти одинаковыми, а третий (борщ) — далеко.

Модель, которая это делает, у нас — OpenAI `text-embedding-3-small`, она
возвращает вектор из **1536 чисел**.

## Как измеряется «похожесть»

Есть математическая операция — **cosine similarity** (косинусная близость).
Она берёт два вектора и возвращает число от -1 до 1:

* `1.0` — тексты идентичны по смыслу;
* `~0.85+` — очень похожи (для нас это «дубль»);
* `~0.5` — что-то общее есть, но темы разные;
* `~0` и ниже — совсем про разное.

Нам не нужно самим это программировать — за нас считает база данных (pgvector).

## Почему это решает проблему «наслаивания»

Наивный подход: «взять ВСЕ прошлые идеи и посты Натальи и вставить их текстом в
промпт, чтобы AI сам решил, не повтор ли это». Проблема: чем больше данных, тем
длиннее промпт → дороже, медленнее, и в какой-то момент просто не влезет.

Векторный подход: мы не суём весь список в промпт. Мы храним по одному вектору
на каждую идею/пост и **ищем только несколько ближайших** (top-K). Неважно,
100 записей в базе или 100 000 — поиск ближайших работает одинаково быстро
(за счёт специального индекса). Промпт при этом вообще не растёт.

Поэтому «удаление старых данных» — это только про здоровье базы, а не про то,
чтобы промпт не раздувался. Раздувания и так нет.

# Часть 2. Как это устроено в нашем проекте

## Стек

| Компонент | Что используем | Зачем |
|-----------|----------------|-------|
| База | Supabase Postgres (уже подключена в `.env.local`) | Основное хранилище |
| Векторное расширение | `pgvector` | Тип `vector` + быстрый поиск ближайших |
| Модель эмбеддингов | OpenAI `text-embedding-3-small` (1536 dim) | Дёшево (~$0.02 / 1M токенов), достаточно точно |
| ORM | Prisma 7 (`@prisma/adapter-pg`) | Схема + обычные запросы |
| Векторные запросы | raw SQL (`$queryRaw`) | Prisma Client не умеет оператор `<=>`, поэтому raw |

> **Почему raw SQL.** Prisma пока не поддерживает тип `vector` и оператор
> близости `<=>` нативно. Поле `embedding` в схеме описывается как
> `Unsupported("vector(1536)")` (Prisma знает, что колонка есть, но не трогает
> её типы), а сам поиск делается через `$queryRaw`. Правила безопасного raw SQL
> — в скиле `prisma-client-api` (`references/raw-queries.md`): всегда
> параметризуем значения, не склеиваем строками.

## Шаг 0. Один раз: включить pgvector

Supabase поддерживает pgvector из коробки, его нужно только включить. Делается
это SQL-миграцией (один раз):

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## Схема БД (Prisma)

Поле `embedding` добавляется в `Idea` и `NataliaPost`. Prisma-модель:

```prisma
model Idea {
  id                String   @id @default(cuid())
  competitorPostId  String
  title             String
  thesis            String
  goal              String
  // pgvector: Prisma хранит как Unsupported, работаем через raw SQL
  embedding         Unsupported("vector(1536)")?
  status            String   @default("NEW")
  createdAt         DateTime @default(now())
}

model NataliaPost {
  id          String   @id @default(cuid())
  text        String
  mainIdea    String
  embedding   Unsupported("vector(1536)")?
  publishedAt DateTime?
  createdAt   DateTime @default(now())
}
```

## Индекс для быстрого поиска

Чтобы поиск ближайших не сканировал всю таблицу, создаём HNSW-индекс под
косинусную близость (тоже raw SQL миграцией):

```sql
CREATE INDEX IF NOT EXISTS idea_embedding_idx
  ON "Idea" USING hnsw (embedding vector_cosine_ops);

CREATE INDEX IF NOT EXISTS natalia_embedding_idx
  ON "NataliaPost" USING hnsw (embedding vector_cosine_ops);
```

При наших объёмах (сотни-тысячи строк) индекс не критичен по скорости, но стоит
копейки и делает поведение предсказуемым при росте.

## Как считаем embedding (в коде)

Живёт в `src/ai/` (клиент OpenAI — в `src/core/lib/`). Сервис в `src/services/`
координирует, репозиторий в `src/repositories/` пишет в БД. Прямых вызовов
Prisma вне репозиториев нет (правило из `ARCHITECTURE.md`).

```ts
// src/ai/embeddings.ts (упрощённо)
import { openai } from "../core/lib/openai";

export async function createEmbedding(text: string): Promise<number[]> {
  const res = await openai.embeddings.create({
    model: "text-embedding-3-small",
    input: text,
  });
  return res.data[0].embedding; // массив из 1536 чисел
}
```

## Как ищем дубликаты (raw SQL через Prisma)

Оператор `<=>` в pgvector — это **косинусное расстояние** (0 = идентичны).
Similarity = `1 - расстояние`. Вектор передаём как параметр в виде строки
`'[0.12,-0.45,...]'` и приводим к типу `::vector`.

```ts
// src/repositories/ideaRepository.ts (упрощённо)
import { prisma } from "../db/client";

const THRESHOLD = 0.85; // выше — считаем дублем

export async function findMostSimilarIdea(embedding: number[]) {
  const vectorLiteral = `[${embedding.join(",")}]`;

  const rows = await prisma.$queryRaw<
    { id: string; title: string; similarity: number }[]
  >`
    SELECT id, title, 1 - (embedding <=> ${vectorLiteral}::vector) AS similarity
    FROM "Idea"
    WHERE embedding IS NOT NULL
    ORDER BY embedding <=> ${vectorLiteral}::vector
    LIMIT 1
  `;

  return rows[0] ?? null;
}
```

Аналогичный запрос — по `NataliaPost`. В сервисе берём максимум similarity из
обеих таблиц и сравниваем с порогом.

> Vector-литерал (`[...]`) собирается из чисел, полученных от OpenAI, а не из
> пользовательского ввода, поэтому склейка тут безопасна. Все прочие значения
> (пороги, id) идут через параметры Prisma.

## Поток дедупликации внутри прогона

```
Для каждой сгенерированной идеи (title + thesis):

  1. embedding = createEmbedding(title + "\n" + thesis)

  2. simIdea    = findMostSimilarIdea(embedding)      // среди уже сохранённых Idea
     simNatalia = findMostSimilarNatalia(embedding)   // среди NataliaPost
     maxSim = max(simIdea, simNatalia)

  3. если maxSim >= 0.85:
        status = DUPLICATE   (не показываем пользователю)
     иначе:
        сохраняем идею как NEW + записываем её embedding в БД
        (теперь она тоже участвует в проверке следующих идей этого прогона)
```

Важный нюанс: embedding **сохранённой** идеи сразу попадает в базу, поэтому если
в одном чанке AI выдал две похожие идеи, вторая отсечётся как дубль первой.

## Где что лежит (по папкам проекта)

| Файл / папка | Ответственность |
|--------------|-----------------|
| `src/ai/embeddings.ts` | Вызов OpenAI embeddings API, возврат вектора |
| `src/core/lib/openai.ts` | Инициализация OpenAI клиента |
| `src/db/client.ts` | Экспорт Prisma Client (адаптер `@prisma/adapter-pg`) |
| `src/repositories/ideaRepository.ts` | raw SQL поиск похожих `Idea`, запись embedding |
| `src/repositories/nataliaPostRepository.ts` | raw SQL поиск похожих `NataliaPost` |
| `src/services/deduplicationService.ts` | Логика «дубль / не дубль», порог, сравнение таблиц |
| `prisma/migrations/*` | `CREATE EXTENSION vector`, колонки `vector(1536)`, HNSW-индексы |

## Настраиваемые параметры

| Параметр | Стартовое значение | Комментарий |
|----------|--------------------|-------------|
| Модель эмбеддингов | `text-embedding-3-small` | Можно поднять до `-large` (3072 dim), если точности не хватит |
| Размерность вектора | 1536 | Должна совпадать с `vector(N)` в схеме |
| Порог дубля | 0.85 | Настраивается по факту: слишком много ложных дублей → поднять; пропускает повторы → опустить |
| top-K | 1 | Для дедупликации хватает ближайшего; при желании смотреть top-3-5 |

## Стоимость (ориентир)

Эмбеддинг одной идеи — это ~50–150 токенов. За прогон ~50 идей → несколько тысяч
токенов → доли цента. Дедупликация (`<=>`) считается в базе и не стоит ничего.
Основные расходы остаются на генерации идей и постов (chat-модель), а не на
векторах.

# Итого одним абзацем

Каждой идее и каждому посту Натальи мы присваиваем вектор смысла (1536 чисел от
OpenAI). Перед показом идеи пользователю база (pgvector) быстро находит самую
похожую из уже существующих; если похожесть выше 0.85 — идея считается повтором
и отбрасывается без всякого обращения к LLM. Это дёшево, быстро и не раздувает
промпт при росте данных.
